# AGENTS.md

Guidance for AI coding agents working in this repository.

## Project

`board_t1_cmake/` is a bare-metal **STM32C542RCT6** (NUCLEO-C542RC) firmware project
generated by CMSIS-Toolbox/STM32CubeMX2. Build: CMake (Ninja).

Three build configurations are supported, each with its own build dir:
**debug_GCC**, **release_GCC** (Arm GCC 14.3.1, newlib-nano) and **release_ARMCLANG**
(ST LLVM `starm-clang`, full newlib). See `README.md` for the full toolchain explanation.

The source of truth is `board_t1.ioc2`; generated code lives under
`board_t1_cmake/generated/` and `board_t1_cmake/user_modifiable/`.

## Build & verify commands

The recommended way to set up tool paths is `bootstrap.ps1` (run it once from
`board_t1_cmake/`; it puts STM32CubeIDE CMake/Ninja/GCC and ST LLVM on `PATH`):

```bat
powershell -NoProfile -ExecutionPolicy Bypass -File bootstrap.ps1
```

Then, from `board_t1_cmake/`:

```bat
cmake --preset release_ARMCLANG_NUCLEO-C542RC    :: or debug_GCC_... / release_GCC_...
```

From `board_t1_cmake\build\<config>` (one of the three build-dir names):

```bat
ninja              :: build board_t1.elf
ninja hex          :: build board_t1.hex
ninja flash        :: program MCU via STM32CubeProgrammer (SWD, under reset)
ninja capture      :: capture UART output from ST-Link VCP (COM port auto-detected)
```

Use the system `cmake` (3.20.5) NOT at all — it cannot read `CMakePresets.json` v3. The ARMCLANG
preset additionally requires the ST LLVM `bin` on `PATH` (bootstrap.ps1 does this).

## Key files

- `board_t1_cmake/main.c` — application entry; 100 ms tick: toggles LD1 every 500 ms and
  prints `SystemCoreClock` every 5 s.
- `board_t1_cmake/retarget.c` — strong `_write`/`__io_putchar` sending `printf` to USART2.
- `board_t1_cmake/cmake/tools.cmake` — custom Ninja targets (`hex`, `flash`, `capture`).
- `board_t1_cmake/capture.ps1` — ST-Link VCP serial capture.
- `board_t1_cmake/generated/hal/mx_gpio_default.c` — GPIO init (PA5 = LD1, PC13 = BTN).
- `board_t1_cmake/generated/hal/mx_usart2.c` — USART2 @ 115200 (PA2 TX / PA3 RX).
- `board_t1_cmake/armclang_runtime.c` — CLANG-only shim providing `__aeabi_read_tp`
  (newlib TLS base). The `__stack`/`__stack_limit` symbols for the ARMCLANG build live in
  the linker script `stm32c542xc_flash.ld`, NOT here (see cautions below).
- `board_t1_cmake/cmake/STLLVM.cmake` — ST LLVM toolchain: selects the ST bundled newlib
  runtime and links it by absolute path via `CMAKE_C_STANDARD_LIBRARIES` (`-nostdlib`
  + `--start-group` over `libcrt0-nosys.a libc.a libm.a libnosys.a libclang_rt.builtins.a`).
- `board_t1_cmake/cmake/GCC.14.3.1.cmake` — Arm GCC toolchain (used for the two GCC presets).
- `board_t1_cmake/cmake/flags.cmake` — per-family compile/link flags; CLANG vs GCC branches,
  plus compiles `-include stddef.h` for CLANG (newlib sysmem needs `<stddef.h>`).
- `board_t1_cmake/cmake/components.cmake` — excludes the DFP "Standalone syscalls/sysmem"
  sources for CLANG (newlib `libnosys.a` supplies the stubs instead).
- `board_t1_cmake/bootstrap.ps1` — pins all tool paths (CMake/Ninja/GCC/ST-LLVM) on `PATH`.

## Conventions & cautions

- Generated files (`generated/`, `user_modifiable/Device/...`) are machine-produced from
  `board_t1.ioc2`; prefer editing the `.ioc2` / regenerating over hand-editing, and be
  aware manual edits there may be overwritten.
- The LED **PA5 is active-low** (open-drain, pin low = on). `init_state` = on (reset).
- USART2 baud is fixed at **115200** in `mx_usart2.c`.
- Do not run `ninja capture` expecting it to return — it blocks until Ctrl+C by design.
- Do not change `cmake/flags.cmake` `-Werror=implicit-function-declaration` flag; declare
  functions in headers.
- **ST clang `-L`/`-l` gotcha**: the ST clang driver mangles `-L <path>` when they arrive as
  separate command-line tokens, so newlib is linked by absolute `.a` path in
  `STLLVM.cmake` (`CMAKE_C_STANDARD_LIBRARIES` is a single string; do NOT switch it back to
  `-L`/`-l`). Also keep `STLLVM_ROOT` = `<tools>` (i.e. `.../tools`, one level up from `bin`),
  not two levels up.
- **ARMCLANG stack symbols must be linker symbols, not C variables.** The CMSIS clang
  header maps `__INITIAL_SP`→`__stack` and `__STACK_LIMIT`→`__stack_limit`, and
  `Reset_Handler` writes them into the M33 `MSPLIM`/`PSPLIM`/PSP registers. They must be
  defined in `stm32c542xc_flash.ld` (`__stack = __StackTop; __stack_limit = __StackLimit;`).
  If `__stack_limit` is instead a C `const` variable, `&__stack_limit` (a flash address)
  gets loaded into MSPLIM and the chip crashes at reset (no UART output). Fixing this
  required editing `user_modifiable/Device/STM32C542RCT6/stm32c542xc_flash.ld`.
- The three build configs are compiler-selected via preset `COMPILER_ID` and must keep using
  separate build dirs so they never overwrite each other.
